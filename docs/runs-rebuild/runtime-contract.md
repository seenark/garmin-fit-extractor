# Implemented Runs runtime contract

This contract describes the software cutover. LT1/LT2 methods remain experimental; reproducible synthetic/native FIT evidence does not establish clinical accuracy or replace the independently licensed human-reference gate in [ADR 0005](../adr/0005-runs-threshold-methods.md).

## Browser API and compatibility

All `/api/v2/runs` data routes require the browser session and return `Cache-Control: private, no-store`. The [route implementation](../../apps/api/src/routes/runs.rs) is authoritative:

- `POST /api/v2/runs/imports`: multipart `files` containing FIT or ZIP; `201` contains ordered item statuses (`imported`, `duplicate`, `unsupported`, `failed`), safe reasons, stable activity IDs and recomputed counts. A failed member does not erase successful members. Direct candidates use FIT content, not case-sensitive filename extensions. ZIP members are inspected without extraction into public storage; unsafe paths and bounded archive failures are explicit.
- `GET /api/v2/runs`: `limit` 1–100, nonnegative `offset`, `sort=startTime`, `order=asc|desc`; defaults are 50, 0 and descending. Ordering uses parsed event timestamps and stable IDs; unknown dates stay null and sort last. List rows contain small summaries, revision IDs, possible-duplicate flags and processing/history state, not full sample documents.
- `GET /api/v2/runs/{id}`: a coherent manifest pins normalized data and actual analysis. Normalized JSON is streamed from immutable chunks; missing/truncated backing data fails the response rather than producing complete JSON. Missing values remain null, not zero.
- `DELETE /api/v2/runs/{id}`: `204` after source and dependent cached data are erased; owner-scoped missing IDs return `404`.
- `POST /api/v2/runs/{id}/reprocess`: `202` queues processing of the existing immutable source and stable activity ID.
- `GET /api/v2/runs/{id}/evidence`, `/thresholds/trend`, `/thresholds/latest`: actual historical/current evidence, not a substitute for explicit export selection.
- `POST /api/v2/runs/exports`: explicit distinct `activityIds`, `mode=coach|full`, `includeLocation` and `includeDeviceIdentifiers`. `201` returns token URL, byte length, expiry and required privacy omissions. Missing/foreign selections return the same `404 NOT_FOUND` before owned legacy/unready classifications; malformed, empty or duplicate selections and owned unready/legacy selections return `422`. No rejected selection mints a partial token.
- `GET` and `HEAD /api/v2/runs/exports/{token}`: owner-scoped pinned transport. HEAD is metadata-only and does not acquire or renew a download lease.

Browser callers move to these routes. Every previously supported browser extraction upload/list/detail/export/delete route now returns authenticated `410 RUNS_ENDPOINT_RETIRED` and unauthenticated `401`; no alias or unredacted fallback remains. Protected CLI schema `1.0.0`, FIT Coach `/api/v1/activities*` and OAuth, auth, Shoes and admin contracts remain separate.

Source-less historical rows expose safe summaries, `sourceUnavailable: true` and `LEGACY_SOURCE_UNAVAILABLE`; normalized data, analysis, historical estimates and revision IDs are null. Reprocess returns `409 SOURCE_UNAVAILABLE`; export returns `422`. Backfill never invents FIT, source IDs, epoch dates or successful numerical results.

## Decoding, storage and publication

The real [decoder](../../apps/api/src/fit/runs.rs) emits decoded/normalized schema `2.0.0` through its writer-only API. Full original sample and RR resolution, ordered typed fields, raw values, source references, validity and missingness remain available. Standard native profile identity, not user-controlled names, establishes metric meaning. Native cadence cycles and verified running steps have distinct units/context. Recorded session values, derived values, covered time, window time and calculation method remain distinct.

The [isolated child](../../apps/api/src/runs/process.rs) starts before Tokio, configuration or DB access. It accepts at most 20 MiB original FIT, writes fixed `run.json` in an owned `0700` directory with `0600` file mode, and emits only a bounded 64 KiB descriptor on stdout. Linux limits remain 512 MiB address space, 60 CPU seconds, 512 MiB file size, one process and no core dump; parent wall timeout remains 60 seconds. A 64 KiB outer write buffer batches hashing/accounting without raising limits or changing document bytes. Parent verifies opened regular-file ownership/mode, exact length, source digest and document digest; private paths never enter responses.

The [streaming validator](../../apps/api/src/runs/stream.rs) addresses decoded/normalized members by checked original-file spans. It does not materialize the full archive as `serde_json::Value` or copy archives into temporary documents. The separate numerical projection retains every original sample/RR and required interval/sensor context while omitting unused metadata. Original document plus projection share the existing 512 MiB workspace budget. Writer/quota/ENOSPC failures stay safe `RUNS_STORAGE_FAILED` processing failures; malformed JSON/semantic evidence stays `INVALID_RUN_DOCUMENT`. Numerical receipts bind the actual projection hash, immutable normalized revision and archived normalized hash.

Numerical-input PostgreSQL query failures retain retryable `RUNS_STORAGE_FAILED` through the JSON reader; malformed JSON, missing chunks and integrity failures remain permanent invalid-document failures. Existing bounded retry count stays three.

Original FIT is immutable owner/hash `BYTEA`; exact bytes resolve duplicate detection. Decoded, normalized and numerical input documents use immutable 64 KiB revision chunks written with binary COPY in the publication transaction. The [store](../../apps/api/src/runs/store.rs) and [durable jobs](../../apps/api/src/runs/jobs.rs) fence publication with live owner/source, desired generation, original job holder and global worker-slot holder. Job completion and coherent manifest publication are atomic, including recovery after worker loss. CPU admission and private artifacts remain held until actual blocking computation drains, even if the requesting future is dropped. FIT child cancellation terminates the child.

Publication execution remains polled concurrently with heartbeat SQL. An original-holder heartbeat waiting on the publication transaction's job-row lock cannot stop that transaction from advancing to commit.

Import/version scanning creates durable work without waiting for a page view. Analysis-only changes can reuse compatible normalized revisions. Independent history epochs continue for the retained coherent manifest while newer processing is pending or fails; ready history means an actual matching result, not a placeholder. Ordinary reprocess/version updates retain published estimates and existing pinned exports. DELETE first tombstones/revokes, repeats dependency revocation under the owner lock to catch concurrently committed exports, waits bounded readers, then erases dependent snapshots/chunks/estimates/receipts/source bytes. Original-holder CAS prevents resurrection or stale cleanup of a new holder. No startup/deploy reset exists.

## Latest targets and export fidelity

Historical targets retain their real activity cutoff and computation time. Evidence verifies each coherent numerical receipt before analysis. Observation groups are not collapsed before target eligibility: every verified member reaches the real engine, which chooses one usable source per target without duplicate pooling or invented confidence.

`latest` returns `evidenceCutoff`, `latestAttempt`, `lastAvailable: {lt1, lt2}`, `stale` and `engineStatus`. Each available target requires a real finite numerical value. A fresh numeric latest attempt participates immediately; an unavailable target can retain an older actual numeric result with its original activity/cutoff/computation metadata and stale flag. A changed history epoch can be stale even when the cutoff text matches. No `lastGood` compatibility alias or fabricated threshold exists.

Full export uses a closed privacy schema over exactly the complete selected set. It preserves allowed sample/RR order, native numeric types/raw values, recorded/derived summary maps, coverage, method literals, source references and explicit missingness. Default policy omits locations, device/account identity, filenames, unknown opaque/developer fields, private paths, FIT bytes and unselected raw history. Independent location/device consents never promote one category into another metric. Required `privacyOmissions` describe omissions without leaking removed values. Coach export declares aggregation/splitting transformations and respects lap, pause, gap, repeat and missing-metric boundaries.

The [export implementation](../../apps/api/src/runs/export.rs) writes one immutable pretty JSON snapshot ending with a newline, using bounded readers/writers rather than full-archive values or a private export file. Repeated GET serves the same pinned bytes with exact `Content-Length`, JSON content type and fixed attachment filename. Initial transport failures have no successful-export headers. Revocation, expiry or missing backing chunks after streaming begins produce a real body/connection error, not clean EOF or misleading complete JSON. GET authorization has an independent finite wall/PG lease: `min(remaining 15-minute snapshot TTL, 30 seconds + ceil(byteLength / 5 MiB))`; HEAD does not extend it. Bytes already delivered before deletion cannot be recalled.

Real native HTTP reciprocal LT1-only/LT2-only crop cases confirm actual numerical results, independent latest target retention with original dates/staleness, and removal after deleting the older source. Their encoded native estimates are approximately 134.6372770392192 and 160.4210626128638 bpm; the smoke runner uses its own `1e-8` bpm comparison tolerance. The independent crop oracle file SHA-256 is `b966a0df425d5bafe057ee916530d02e6426e926d4a2c898ef2004d802a8eacb`; its frozen boundary tolerance is 0.005 seconds, not a declared numerical estimate tolerance.

Final integration owns whole-workspace validation, actual native 100k HTTP/Linux resource proof, browser clipboard/download failure and capacity proof, charts/share PNG proof, final formatting/source-hash refresh and deploy/backup/restore gates. Core scoped tests or synthetic fixtures do not substitute for those measurements or independently licensed human physiological references. Browser Copy keeps the approved exact response-text/clipboard path pending actual capacity evidence; Download uses native browser transport, not an invented success fallback.
